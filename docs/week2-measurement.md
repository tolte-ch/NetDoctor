# NetDoctor 2주차 측정 엔진

## 구현 범위

2주차에는 실제 DNS, TCP, TLS, TTFB, 다운로드 처리율, RTT 측정을 구현했다. 각 측정은
5~10회 반복되며 원본 표본과 평균, 중앙값, 최솟값, 최댓값, 표준편차가 JSON에 함께
저장된다. ping 실패 횟수로 패킷 손실률도 계산한다.

## 측정 경계

- DNS는 `getaddrinfo()` 호출부터 TCP 엔드포인트 반환까지 측정한다.
- TCP는 DNS에서 얻은 IP 주소로 직접 연결하므로 DNS 시간이 포함되지 않는다.
- HTTPS에서는 TCP 연결 뒤의 TLS 핸드셰이크를 보조 지표로 별도 측정한다.
- TTFB는 연결된 소켓에 HTTP 요청을 쓰기 시작한 때부터 첫 응답 바이트까지다.
- 다운로드 처리율은 응답 헤더와 첫 본문 바이트를 받은 뒤의 본문 전송만 계산한다.
- RTT는 운영체제의 `ping` 명령 결과에서 추출한다.

## 실패 상태

- `success`: 요청한 반복이 모두 성공했다.
- `partial`: 일부 표본은 성공했고 일부 시도는 실패했다.
- `unavailable`: 설정이 없거나 측정 방식이 적용되지 않는다.
- `failed`: 성공한 표본이 하나도 없다.

한 지표의 실패는 다른 지표와 다음 반복을 중단하지 않는다. 모든 ping 시도가 실패하면
ICMP 차단과 실제 패킷 손실을 구분할 수 없으므로 손실률을 100%로 단정하지 않고
`unavailable`로 기록한다.

## 안전 제한

실제 측정 명령은 `--config`가 없으면 실행되지 않는다. 다운로드는 설정한 최대 바이트와
최대 시간 중 먼저 도달한 제한에서 멈춘다. 사용자는 본인이 관리하거나 측정을 허용받은
서버만 설정해야 한다.

## 알려진 한계

- DNS 값은 운영체제와 재귀 DNS 캐시의 영향을 받는다.
- 운영체제마다 ping 명령 형식과 ICMP 정책이 다를 수 있다.
- 다운로드 값에는 대상 서버, CDN, 캐시, 서버 측 속도 제한의 영향이 포함된다.
- TTFB는 최초 HTTP 응답을 측정하며 리다이렉션 이후 최종 페이지의 전체 시간은 아니다.
- 로컬 테스트 설정은 HTTP를 사용하므로 TLS는 정상적으로 `unavailable`로 표시된다.
