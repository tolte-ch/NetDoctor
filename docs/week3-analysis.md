# NetDoctor 3주차 분석 규칙

## 목표

3주차에는 2주차 측정값을 사용자가 이해할 수 있는 설명으로 바꾸는 규칙 기반 분석기를
구현한다. 측정기와 분석기를 분리하며, 모든 판정은 관측 근거와 불확실성 문구를 함께
반환한다. 따라서 프로그램은 가능성을 설명하지만 원인을 확정했다고 표현하지 않는다.

## 대표값과 기준

분석에는 이상치의 영향을 덜 받는 각 지표의 중앙값을 사용한다. 현재 기준은 초기 실험용
휴리스틱이며 5주차 환경별 검증 결과로 조정한다.

| 규칙 | 초기 기준 | 해석 |
|---|---:|---|
| DNS 지연 | `dns > 100 ms` | 이름 조회 단계 지연 가능성 |
| 높은 RTT + 낮은 처리율 | `rtt > 100 ms`, `download < 10 Mbps` | 장거리 경로 또는 혼잡 가능성 |
| 낮은 RTT + 낮은 처리율 | `rtt <= 50 ms`, `download < 10 Mbps` | 액세스 링크·Wi-Fi·서버 제한 가능성 |
| 높은 RTT | `rtt > 150 ms` | 상호작용·실시간 서비스 지연 가능성 |
| 느린 HTTP 응답 | `ttfb > 500 ms` | 서버 처리 또는 응답 경로 지연 가능성 |
| 느린 TCP 설정 | `tcp > 200 ms` | 새 연결 설정 지연 가능성 |
| 패킷 손실 | `>= 1%` 경고, `>= 5%` 심각 | 재전송·실시간 품질 저하 가능성 |

조합 규칙은 단일 수치보다 우선한다. 예를 들어 RTT와 처리율이 함께 나쁘면 `높은 RTT`
두 개를 따로 보여주는 대신 `장거리 경로 또는 혼잡 가능성` 하나로 설명한다.

## 서비스 적합도

- 웹 브라우징: DNS, TCP, TTFB를 함께 평가한다.
- 1080p/4K 스트리밍: 다운로드 처리율을 중심으로 패킷 손실을 반영한다.
- 화상회의: RTT와 손실을 중심으로 다운로드 처리율을 보조적으로 반영한다.
- 필수 지표가 없으면 별점을 억지로 계산하지 않고 `0/5, 판단 불가`를 반환한다.

화상회의는 아직 업로드 처리율과 지터를 측정하지 않으므로 수신 측 관점의 추정이라는
한계를 항상 표시한다. 영상 서비스의 실제 비트레이트와 측정 서버 제한도 결과에 영향을
줄 수 있다.

## 결과 계약

CLI의 `demo`와 `measure` JSON은 스키마 `1.2`로 분석 결과를 포함한다.

- `overall_rating`, `overall_label`, `summary`: 종합 평가
- `primary_bottleneck`: 가장 심각한 병목 후보
- `evidence`: 종합 평가에 사용한 대표값
- `findings[]`: 규칙 코드, 심각도, 설명, 근거, 불확실성
- `suitability[]`: 서비스별 별점, 설명, 근거, 불확실성
- `uncertainty`: 한 대상·한 시점 측정이라는 전체 한계

원본 표본과 통계는 그대로 보존된다. 분석기는 측정 결과를 변경하지 않는다.
